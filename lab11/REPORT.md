## Вариант 2. Карточка студента

**Условие.** `StudentCard` получает имя, группу и специальность через props; кнопка показывает/скрывает подробности.

### Схема компонентов и потоков данных

```
App  (массив students)
 ├─ props: name, group, specialty, course, email ─▶ StudentCard #1
 ├─ props: ...                                   ─▶ StudentCard #2
 └─ props: ...                                   ─▶ StudentCard #3
                    state внутри каждой карточки: showDetails, isFavorite
```

### Props и state

- **Props** (только чтение): `name`, `group`, `specialty`, `course`, `email`.
- **State** (локальный, у каждой карточки свой): `showDetails` — видимость подробностей; `isFavorite` — отметка «в избранном».
- Изменение состояния — только через сеттеры `setShowDetails`, `setIsFavorite` (в функциональной форме `v => !v`).

### Тесты

| № | Действие | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|
| 1 | Открыть страницу | Три карточки с именем, группой, специальностью; подробности скрыты, кнопка «Показать подробности» | | |
| 2 | Нажать «Показать подробности» у первой карточки | Появляются курс и email; текст кнопки меняется на «Скрыть подробности» | | |
| 3 | Нажать кнопку повторно | Подробности скрываются | | |
| 4 | Нажать «☆ В избранное», затем «★ Убрать из избранного» | Рамка карточки становится жёлтой и возвращается обратно; статус в подробностях меняется | | |
| 5 | Раскрыть подробности только у первой карточки (граничная проверка независимости) | Вторая и третья карточки остаются свёрнутыми | | |

## Вариант 3. Переключатель темы

**Условие.** `ThemeSwitch` получает названия тем через props, выбранную тему хранит в state.

### Схема компонентов и потоков данных

```
App  state: theme, changes
 ├─ props: title, themes, selected, onChange ─▶ ThemeSwitch
 │                                    ◀─ onChange(id) — событие вверх
 └─ props: themeLabel, changes               ─▶ ThemePreview
```

### Props и state

- **Props:** `title`, `themes` (массив `{id, label}`), `selected`, `onChange` для `ThemeSwitch`; `themeLabel`, `changes` для `ThemePreview`.
- **State** (в родителе `App`): `theme` — выбранная тема; `changes` — число смен темы. State поднят в родителя, потому что от темы зависят оба дочерних компонента и фон страницы («подъём состояния»).
- Обработчик `handleChange` передаётся ребёнку как функция, а не вызывается сразу.

### Дополнительное задание

Выбранная тема сохраняется в `localStorage` и восстанавливается при перезагрузке; некорректное сохранённое значение игнорируется. В state хранятся изменяющиеся данные (`theme`, `changes`), через props передаются неизменяемые для ребёнка данные (список тем, подпись, обработчик).

### Тесты

| № | Действие | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|
| 1 | Открыть страницу | Выбрана «Светлая», «Количество смен темы: 0» | | |
| 2 | Нажать «Тёмная» | Меняются цвета страницы; в предпросмотре «Тёмная», смен: 1 | | |
| 3 | Нажать «Океан» | Тема «Океан», смен: 2 | | |
| 4 | Повторно нажать уже выбранную тему | Счётчик смен не увеличивается | | |
| 5 | Выбрать «Тёмная», нажать «Сброс» | Возвращается «Светлая», смен: 0 | | |
| 6 | Выбрать «Океан», обновить страницу (F5) | Тема «Океан» сохранилась | | |

## Вариант 4. Мини-таймер без автоматического отсчёта

**Условие.** Кнопки добавляют и уменьшают минуты; начальное значение приходит через props.

### Схема компонентов и потоков данных

```
App
 ├─ props: label="Подготовка…", initialMinutes=15, step=5, maxMinutes=60 ─▶ Timer #1
 └─ props: label="Перерыв",     initialMinutes=10, step=1, maxMinutes=30 ─▶ Timer #2
                         state внутри каждого Timer: minutes
```

### Props и state

- **Props:** `label`, `initialMinutes`, `step`, `maxMinutes`.
- **State:** `minutes` — текущее значение; инициализируется из `initialMinutes`. Props не изменяются: сброс возвращает `minutes` к `initialMinutes`.
- Граничные значения: результат ограничивается диапазоном `[0, maxMinutes]`, соответствующие кнопки блокируются, выводится пояснение.

### Тесты

| № | Действие | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|---|
| 1 | Открыть страницу | Таймер 1 — 00:15, таймер 2 — 00:10 | | |
| 2 | Нажать «+5 мин» у таймера 1 | 00:20 | | |
| 3 | Нажать «+5 мин» ещё раз | 00:25 (повторное действие) | | |
| 4 | Нажать «Сброс» | 00:15 | | |
| 5 | Нажимать «−5 мин» до нуля | 00:00; кнопка «−» заблокирована, сообщение о минимуме | | |
| 6 | Нажимать «+5 мин» до 60 | 01:00; кнопка «+» заблокирована, сообщение о максимуме | | |
| 7 | Изменить таймер 1 и посмотреть таймер 2 | Таймер 2 не изменился (независимость) | | |

> Колонки «Фактический результат» и «Статус» заполняются при прогоне приложения (`npm run dev`).

## Вывод

Реализованы три приложения на React с использованием компонентного подхода. Данные от родителя к дочерним компонентам передаются через props (только чтение), изменяемые данные хранятся в state через `useState`, события от ребёнка к родителю передаются функциями-обработчиками. Независимость экземпляров компонентов подтверждена на карточках и таймерах.

## Ответы на контрольные вопросы

1. **Компонент** — независимая часть интерфейса со своей разметкой и поведением (в React — функция, возвращающая JSX).
2. **Props** — способ передать данные от родителя к дочернему компоненту и настроить его.
3. **Props — входные данные**, потому что задаются родителем; ребёнок не должен их менять.
4. **State** — данные компонента, изменение которых вызывает перерисовку.
5. **useState(initial)** возвращает пару `[значение, сеттер]`; вызов сеттера запоминает новое значение и запускает рендер.
6. **Повторный рендер** происходит при изменении state, при получении компонентом новых props и при повторном рендере родителя.
7. **Click:** `<button onClick={handleClick}>` — передаётся функция, а не её вызов.
8. **Прямое присваивание** не сообщает React об изменении, интерфейс не обновится; изменения делают через сеттер.
9. **State** принадлежит самому компоненту и им меняется; **props** приходят снаружи и только читаются.
10. **Обработчик ребёнку:** родитель передаёт функцию как prop (`onChange={handleChange}`), ребёнок вызывает её при событии.
11. **Управляемое поле ввода** — поле, значение которого хранится в state (`value={text}` + `onChange`).
12. **Независимость экземпляров:** отрендерить два компонента, изменить один и убедиться, что второй не изменился (вариант 2 и 4).
